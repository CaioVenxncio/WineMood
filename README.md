# WineMood

**WineMood** is an NLP research project on the language of professional wine
tasting notes. It asks how much of a critic's numeric score can be recovered
from the text they wrote, and which language carries that signal.

The project started in 2025 as a coursework "wine review sentiment classifier".
A 2026 audit found three problems:
- its labels were critic-score thresholds rather than sentiment;
- one of its three classes cannot occur in the data;
- no results had ever been recorded.

The project is being rebuilt as a reproducible research codebase in five
phases (see [`docs/roadmap.md`](docs/roadmap.md)).

> **Current status (Phase 2 complete, pending review):** the real dataset is
> acquired, checksummed and validated. The research formulation is decided,
> the split protocol is implemented and verified, and the Phase 3 evaluation
> protocol is pre-registered. **No model has been trained under the new
> methodology and no performance results exist yet.** Modelling is Phase 3.

## Research formulation

**Primary task:** regression of the critic's score (80–100 points) from the
tasting-note text.

**Secondary tasks:**
- ordinal classification into Wine Enthusiast's published rating categories;
- binary classification of ≥ 90 points.

This is **not** sentiment analysis. The dataset has no sentiment annotations,
and the old "Negative" class (< 80 points) is empty, because the publication
does not review such wines. See
[`docs/problem-formulation.md`](docs/problem-formulation.md).

## What is implemented

| Component | Status |
|---|---|
| Audit | [`docs/audit.md`](docs/audit.md): 30 findings with evidence and verification logs |
| Problem formulation | [`docs/problem-formulation.md`](docs/problem-formulation.md): three formulations compared, decision recorded |
| Research proposal | [`docs/research-proposal.md`](docs/research-proposal.md): RQs, hypotheses, ethics, verified references |
| Experimental protocol | [`docs/experimental-protocol.md`](docs/experimental-protocol.md): baselines, metrics, statistics (pre-registered) |
| Data report | [`docs/data-report.md`](docs/data-report.md): generated by code from the checksummed dataset |
| Data pipeline | `winemood data download / verify / validate / split / eda` |
| Targets | Versioned schemes: `points_regression_v1`, `we_category_v1`, `we_category_merged_v1`, `points_binary_90_v1`, plus the deprecated legacy `points_band_v0` |
| Split protocol | Exact deduplication, MinHash near-duplicate and same-wine grouping, stratified 70/10/20 split, taster-held-out split, isolation assertions, committed fingerprints |
| Streamlit app | English UI serving the *legacy* LSTM if you supply its artifacts. It explains what is missing otherwise |
| Tests and CI | pytest on synthetic data (no dataset or network needed), Ruff, GitHub Actions workflow (not yet run on GitHub) |

**Not yet implemented** (Phase 3+):
- training and evaluation pipelines;
- baselines and models;
- reproducible model artifacts;
- a UI aligned with the new targets.

## Key data facts (from the generated report)

- 129,971 reviews. After removing 10,017 duplicate texts, 119,954 remain.
- Scores are integers from 80 to 100: mean 88.44, SD 3.09.
- Review length correlates with score (Spearman ρ = 0.51), so a length-only
  baseline is mandatory.
- 19 named tasters, and 24,912 deduplicated reviews have no taster.

## Quick start

Requires Python 3.11–3.13.

```bash
git clone https://github.com/CaioVenxncio/WineMood.git
cd WineMood
python -m venv .venv
# Windows: .venv\Scripts\activate    macOS/Linux: source .venv/bin/activate
pip install -e ".[dev]"

pytest                          # test suite (synthetic data)
ruff check . && ruff format --check .

winemood data download          # ~17 MB; verifies the pinned SHA-256
winemood data validate
winemood data split             # ~2 min; writes manifests + fingerprints
winemood data split --check     # reproducibility check
winemood data eda --publish     # regenerates docs/data-report.md

streamlit run app.py            # demo UI (legacy model, if artifacts supplied)
```

See [`data/README.md`](data/README.md) for provenance and fallbacks, and
[`artifacts/README.md`](artifacts/README.md) for the legacy model layout.
